# マイクロサービスルートのCLAUDE.md生成

カレントディレクトリ(複数リポジトリが並ぶルート)を調査し、Claude/AIエージェントがこのディレクトリで作業を始めた瞬間に全体構造を理解できるCLAUDE.mdを生成する。

## 原則

- **推測で書かない**。調査で確認できたことだけを書き、不明な箇所は「TODO: 要確認」と明記してユーザーに埋めてもらう
- 既にCLAUDE.mdがある場合は上書きせず、現状との差分を提案する
- 内容は簡潔に保つ(全体で100行程度まで)。詳細は各リポジトリのREADME/CLAUDE.mdへのポインタにする

## 調査手順

1. 配下のgitリポジトリを列挙する: `ls -d */.git | sed 's|/.git||'`
2. 各リポジトリについて調べる(READMEの冒頭と設定ファイルを読む):
   - 言語・フレームワーク: `mix.exs` / `package.json` / `go.mod` / `Cargo.toml` / `Gemfile` 等から判定
   - 役割: READMEの冒頭から1行に要約
   - 起動・テスト方法: `Makefile` / `package.json`のscripts / `docker-compose.yml` / `mise.toml` 等から
3. サービス間の通信関係を調べる(横断grep):
   - HTTP/gRPCの呼び出し先: 他サービス名・URL・環境変数(`*_URL`, `*_HOST`等)を検索
   - 非同期連携: キュー名・トピック名(SQS/PubSub/RabbitMQ/Kafka等のクライアント初期化箇所)を検索
   - 共有スキーマ: protoファイル、OpenAPI定義、共有ライブラリの参照
4. 共通のインフラ・ツール: ルート直下のdocker-compose、Terraform、CI設定を確認

## 生成するCLAUDE.mdの構成

```markdown
# <ディレクトリ名> サービスマップ

<この一群が何のシステムかを1〜2行で>

## サービス一覧

| リポジトリ | 言語/FW | 役割 | 起動 | テスト |
|-----------|---------|------|------|--------|
| <名前> | <Elixir/Phoenix等> | <1行要約> | <コマンド> | <コマンド> |

## サービス間の関係

<呼び出し関係を箇条書きかmermaidで。例:>
- api-gateway -> user-service (HTTP, USER_SERVICE_URL)
- order-service -> notification-service (SQS: order-events)

## 横断作業のガイド

- コードを探すとき: <どのリポジトリから見るべきか、命名規則など>
- 共通の規約: <フォーマッタ、ブランチ運用、PRルールなど確認できたもの>
- 触ってはいけないもの: <生成コード、vendorディレクトリなど>

## 各リポジトリの詳細

各リポジトリのREADME(あればCLAUDE.md)を参照する。
```

## 仕上げ

- 生成後、「TODO: 要確認」の箇所を一覧にしてユーザーに確認を依頼する
- 内容が確認できたら、このCLAUDE.mdの保守方法を伝える: サービスの追加・削除時にこのファイルを更新する(または再度このスキルを実行する)
